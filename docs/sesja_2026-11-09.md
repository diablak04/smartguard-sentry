## 3. KLUCZOWA DECYZJA: IFF/BLE na ESP32 (nie na PC)

**Problem:** komputer deweloperski (desktop) **nie ma adaptera Bluetooth**
(`Get-PnpDevice -Class Bluetooth` → pusto; bleak: „No Bluetooth adapter found").

**Decyzja:** skanowanie BLE dla IFF (swój/wróg) robi **ESP32** (ma wbudowane BLE),
a NIE komputer przez `bleak`. **Dongiel USB BT niepotrzebny.**

**Konsekwencje:**
- `ble_scanner.py` (Python/bleak) → tylko opcjonalny fallback, nieużywany.
- Firmware ESP32 dostanie zadanie skanu BLE → wysyła do PC: `IFF:<0/1>,<rssi>`.
- `rules.py` (PC) czyta status IFF z portu szeregowego, nie z bleak.
- Test IFF możliwy dopiero gdy ruszy firmware (Faza 3–4).
- Bonus: RSSI mierzony od wieżyczki = trafniejszy dla celowania.

**Do listy zakupów:** brelok BLE ze stałym MAC (strona „swojego"). Dongla USB NIE kupujemy.

## 7. UWAGA przy przenoszeniu na laptopa

- Kod (pliki `.py`, `config.json`, `firmware/`) przenosi się normalnie / przez `git clone`.
- **Venv (`.venv`) NIE przenosić** — jest związany ze ścieżką/maszyną. Na laptopie zrobić nowy:
  ```
  python -m venv .venv
  .venv\Scripts\python.exe -m pip install ultralytics opencv-python bleak pyserial fastapi uvicorn python-dotenv requests
  ```
- `yolo11n.pt` pobierze się sam przy pierwszym uruchomieniu (albo skopiuj plik).
- `.env` z sekretami NIE jest w gitcie — przenieś ręcznie, gdy uzupełnisz.
- Jeśli laptop **ma Bluetooth**, można tam przetestować `ble_scanner.py` (fallback) — ale docelowo IFF i tak robi ESP32.
